# Stage 7：Harness 质量验收

Stage 5 解决安全恢复，Stage 6 提供可控偏好；Stage 7 将这些能力放进可重复的
**离线验收门禁**。它回答“本次修改有没有破坏核心行为”，不声称模型已经像 OpenCode
一样成熟，也不把测试通过率当作模型智能评分。

## 一键运行

在项目根目录，使用已安装开发依赖的环境：

```bash
.venv/bin/python scripts/evaluate_harness.py
```

新环境先安装 `python3 -m pip install -e '.[dev]'`，再使用同一 Python 运行脚本。
默认输出到 `data/evaluations/<时间戳>-<随机标识>/`，每次创建新目录，不覆盖旧结果：

- `report.md`：六类能力的通过/总数、失败用例和边界说明。
- `report.json`：机器可读逐用例结果、执行时长、Python/平台、源代码指纹、报告版本。

成功退出 `0`；任何不完整或失败验收退出 `1`。JSON 保留底层 pytest 退出码，
`124` 表示整套超时，`127` 表示进程无法启动，`130` 表示用户中断。

```bash
# 只诊断恢复能力；报告会明确标记为 subset，不能替代完整验收
.venv/bin/python scripts/evaluate_harness.py --group recovery

# 自定义保存位置和整套超时时间
.venv/bin/python scripts/evaluate_harness.py --output data/my-eval --timeout 180
```

## 验收范围

| 门禁 | 检查什么 | 不代表什么 |
| --- | --- | --- |
| journey | 主题确认、只读问题、文章修订、恢复、预览指纹和发布审批 | 真实模型总能正确理解意图 |
| events | 同一事件协议、持久化顺序和实时/回放投影 | 分布式消息系统保证 |
| streaming | 两种 Provider 协议、首 token 元信息、批处理、stalled、取消与重试边界 | 真实服务的首 token 延迟或 SLA |
| recovery | 阶段中断、子进程退出、工具复用、外部结果核对和预算 | 远端服务 exactly-once |
| memory | 确认门禁、范围隔离、相关性、过期、编辑冲突、忘记与暂停 | 语义长期记忆或完整隐私擦除 |
| presentation | 三种终端尺寸、角色标识、预览指纹/资源限制及浏览器回退契约 | 微信最终渲染或真实浏览器视觉验收 |

每个门禁必须覆盖指定测试文件，并且所有收集到的用例都通过。
跳过、xfail/xpass、只收集到零条、缺少文件、收集失败、teardown 失败、超时均不能给绿灯。
不设置“允许一部分安全测试失败”的平均分阈值。

跨阶段 golden journeys 使用脚本化 Provider 决策，真正执行 Controller、Harness、
Runtime、记忆服务和预览状态投影，验证：

1. 主题选题 → 新控制器恢复 → 讨论而不选题 → 明确选择 → 写作 → 修订 → 预览内容指纹变化 → 创建草稿请求 → 拒绝审批。
2. 偏好提议 → 人工确认 → 新会话读取 → 本次参数覆盖 → 忘记 → 第三个会话不再检索该偏好。
3. 即使偏好正文包含“自动批准发布”，模型也没有批准接口，真实草稿仍停在审批边界。

第三项验证确定性的接口权限，不是对所有提示注入攻击的语义鲁棒性证明。
本轮不自动调用付费模型、不联网获取论文、不上传微信或飞书，也不打开实际浏览器。

## 运行隔离与报告隐私

脚本在独立子进程执行，环境变量使用白名单，不继承 API Key、pytest 过滤参数或用户插件。
加载配置前屏蔽项目 `.env`，把应用数据、会话、编辑默认值和 Runtime 工作区重定向至临时目录。
Python 审计钩子阻止测试及其 Python 子进程的网络连接/DNS 请求；浏览器启动需要被测试显式 mock。
被阻止的网络尝试也会使整套验收失败，即使应用的 fallback 吞掉了异常；报告只记录次数。
这些措施用于防止测试意外调用外部服务，**不是运行不可信代码的安全沙箱**。

报告仅保存 node ID、通过/失败/跳过、失败阶段、耗时等元信息。
不保存原始 traceback、聊天正文、工具输出、环境变量或 API Key。
测试原始输出写入临时文件并在结束时清理，因此诊断失败请运行报告里的用例：

```bash
# 用报告中的真实 node ID 替换下面的例子
.venv/bin/python -m pytest -q tests/test_stage7_journeys.py::test_golden_research_restore_write_revise_preview_then_reject_draft
```

直接 pytest 不启用上述专用评测隔离器，选中的测试仍使用离线 fixtures；避免混入需要真实服务的测试。
POSIX 超时/中断会终止整个测试进程组；Windows 只保证终止测试父进程。

代码指纹覆盖 `src/`、`tests/`、`scripts/` 下的 Python/JSON 文件和 `pyproject.toml`，包含未提交实现。
它用于区别源码版本，不是包含依赖锁、环境或所有资源的可复现构建证明。
报告里的耗时仅是当前机器上的测试耗时，不计算真实模型延迟分位数。

## CI 和后续门槛

现有 CI 在 Python 3.10/3.11/3.12 上运行全量 pytest，再运行此完整离线验收并上传报告。
报告上传使用 `always()`；如果之前的步骤失败导致验收未运行，将提示没有文件，不能算验收通过。
修改工作流文件不会自动运行远端 CI，需提交推送后观察实际结果。

新增能力应先补以下一种证据：对应契约用例、跨阶段 golden journey、故障注入或终端交互测试。
手动检查终端截图和真实用户试用仍不可替代。下一层评估是独立的**真实模型任务集**：
需要固定提示与人工标注、Provider/模型版本、费用预算、显式同意和禁发布隔离；本轮不暗中启用。
